아니므로 `assets/` 가 아니라 여기 둔다.

## 보고 넘어갈 것

- **HUD 은 목업 기준으로 삼지 않는다.** 상단 좌측 체력 바·일차 표시는 A1 확정 배치와
  일곱 중 여섯이 다르고, 로드맵 8/5 9번에서 `hud.ts` DOM 을 A1 쪽으로 다시 짠다.
  지금 캡처의 HUD 은 **재배치 전** 모습이다.
- **필드도 목업 기준이 아니다.** 아직 플레이스홀더 도형만 그린다. A1 에셋 통합은
  로드맵 8/5 8번이다.
- 즉 이 캡처에서 확정으로 볼 것은 **정비 허브와 대화 모달의 DOM 배치**뿐이다.
- 8·9번이 끝나면 위 두 줄이 반대가 되므로 **캡처를 다시 찍고 이 문단을 지운다**
  (로드맵 실행 순서 11번). 그때까지는 이 문단이 맞다.

## 화면별 메모

### 정비 허브

- 좌측 보관함 상시 영역 (`소지금` + `수확물`·`재료`·`무기`·`소모품` 네 갈래),
  상단 기능 버튼 4개, 우하단 정비 종료 버튼.
- 종료 버튼 문구는 그날 습격 여부로 하나만 나온다 (`DEC-UI-014`). 캡처는 습격이 없는
  1일차라 `아침까지 잔다` 이고, 습격일이면 `밭을 정찰하러 간다` 가 대신 나온다.
- `-filled` 는 항목 행(이름 + 수량)이 그려진 모습을 보려고 **개발 통로로 무기를 채웠다.**
  제작 비용도 숙련도 해금도 거치지 않았으므로 수량과 종류는 실제 플레이와 다르다.
  배치만 참고한다.

### 전투 전 대화

- `dialogue-modal.ts` 하나가 전투 전 대화와 투항 대화를 **함께** 그린다
  (`DEC-UI-010` — 같은 표시·입력 규칙). 투항 대화도 이 배치다.
- 선택지 두 번째가 흐리게 나온 것은 **자원 부족으로 못 고르는 상태**다
  (`수확물 10개 (보유 0)`). 불가능한 선택지 표시 방식이 여기 같이 보인다.
- 대화가 열려 있는 동안 전투가 멈춘다 (`DEC-INPUT-009`).

## 다시 찍는 방법

`npm run dev` 로 띄운 개발 빌드에서 브라우저 콘솔로 흐름을 민다. 개발 통로(`__dev`)는
정비 허브·대화 모달이 들어와 오늘 제거 대상이므로, 아래는 정상 흐름만 쓴다.

```js
// 정비 허브 — 개발 빌드는 1일차 재배까지 자동으로 온다
__scenes.send({ type: 'farming_time_expired' })

// 전투 전 대화 — 1일차는 습격이 없어 2일차까지 간다
__scenes.send({ type: 'maintenance_finished', intent: 'sleep_until_morning' })
__scenes.send({ type: 'confirm' })   // 밤 결과 → 2일차 시작
__scenes.send({ type: 'confirm' })   // 2일차 시작 → 재배
__scenes.send({ type: 'farming_time_expired' })
__scenes.send({ type: 'maintenance_finished', intent: 'scout_field' })
```
