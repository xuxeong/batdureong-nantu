# 밭두렁난투 UI/UX 준비도 및 AI 진행 가이드

- 갱신일: 2026-08-04
- 대상: UI/UX 기획 담당자와 UI/UX 기획 보조 AI
- 저장소 최상위 규칙: `AGENTS.md`
- 함께 입력할 문서:
  1. `밭두렁난투_기획_결정로그_현재본.md`
  2. `밭두렁난투_시스템_UIUX_기획서_현재본.md`
  3. `밭두렁난투_UIUX_준비도_점검.md` (이 문서)

이 문서는 `밭두렁난투_콘텐츠_데이터_준비도_점검.md`와 같은 성격의 문서다. 콘텐츠 CSV 대신
`DEC-UI-*` 결정 하나하나를 다룬다는 점만 다르다.

## 1. 이 문서를 사용하는 방법

AI는 `AGENTS.md`를 최상위 프로젝트 규칙으로 먼저 적용하고, 위 세 파일을 한꺼번에 읽는다.

이 문서는 AI가 세 기준 문서를 읽은 뒤 `DEC-UI-*` 보류 항목을 다루는 순서를 제시하고, 담당자와
한 항목씩 확정해 나가는 실행 지시문이다. 콘텐츠 CSV와 달리 UI/UX 산출물은 콘텐츠 CSV로
저장하지 않는다 — `밭두렁난투_시스템_UIUX_기획서_현재본.md` 13절이 명시하듯 **콘텐츠 CSV에는
임의의 화면 좌표·정렬·연출 값을 넣지 않는다.** UI/UX 산출물의 단일 원본은 결정 로그의
확정 `DEC-UI-*` 항목이며, 시스템·UI/UX 기획서 13절은 그 확정 내용을 요약해 보여주는
파생 문서일 뿐이다.

처음부터 모든 보류 항목을 한 번에 확정하지 않는다. AI는 먼저 의존성을 분석해 진행 순서를
제시하고, 담당자가 시작을 승인하면 한 항목의 시스템 설명과 확정 DEC 후보 문안만 제공한다.
담당자가 수정·확정하기 전에는 다음 항목으로 넘어가지 않는다.

## 2. 문서 권한과 충돌 처리

AI는 다음 우선순위를 반드시 지킨다.

1. `AGENTS.md`
2. 결정 로그의 폐기되지 않은 최신 DEC
3. 시스템·UI/UX 기획서
4. 이 UI/UX 준비도 및 AI 진행 가이드

규칙:

- `확정` DEC는 시스템 제약으로 사용한다.
- `보류` DEC는 재검토 조건이 충족된 UI/UX 작업 항목으로만 다룬다.
- 문서 사이에 충돌이 있으면 진행을 멈추고 충돌한 문장, DEC ID와 추천 해결안을 보고한다.
- 결정 로그에 없는 게임 규칙을 UI 편의를 이유로 임의로 만들지 않는다. 예를 들어 화면에
  새로운 판정·수치·상태를 표시하려면 그 값이 이미 확정 DEC의 런타임 상태로 존재하는지
  먼저 확인한다. 존재하지 않으면 UI 결정이 아니라 시스템 기획 문제로 보고한다.

## 3. AI의 역할

1. 세 문서의 현재 상태와 관련 DEC를 읽는다.
2. `DEC-UI-*` 항목의 의존성을 분석해 진행 순서를 제시한다 (아래 5절이 출발점).
3. 현재 단계에서 다루는 화면·기능이 실제 플레이에서 어떻게 작동하는지 확정 DEC 근거와 함께
   설명한다.
4. 그 화면·기능에 필요한 정보·상호작용 요소를 나열한다.
5. 배치·흐름·피드백 방식에 대한 대안을 텍스트로 2~3개 제시하고 트레이드오프를 설명한다.
   **이 저장소의 산출물은 와이어프레임이 아니라 텍스트 스펙이다.** ASCII 목업이나 좌표를
   임의로 만들지 않는다.
6. 확정 DEC 후보 문안을 제시한다.
7. 사람이 명시적으로 승인한 뒤에만 결정 로그에 반영하고 다음 항목으로 넘어간다.
8. 시스템 질문에는 결정 로그의 DEC ID와 상태를 근거로 답한다.
9. 사실·가정·제안·확인 필요를 섞지 않는다.

AI는 결정 로그를 스스로 확정하지 않는다. `보류` 상태였던 항목을 채택하면 같은 ID를 유지한 채
`확정` 형식(상태·결정일·결정)으로 바꾼다 (`AGENTS.md` 5.2절).

## 4. 첫 응답에서 AI가 해야 하는 일

이 문서로 UI/UX 작업을 처음 시작하는 AI는 다음을 먼저 출력한다.

- 읽은 세 파일명
- 결정 로그 기준 `DEC-UI-*` 확정·보류 수
- 5절 진행 순서표를 그대로 쓸지, 더 나은 순서를 제안할지와 이유
- 추천 첫 단계와 시작 승인 요청

## 7. 항목별 AI 출력 형식

담당자가 한 항목을 시작하라고 승인하면 AI는 반드시 다음 순서로 답한다.

### 7.1 현재 항목

- 단계 번호와 대상 DEC
- 이미 확정된 선행 DEC
- 아직 확정되지 않은 선행 항목과 처리 방식 (있다면 먼저 알린다)

### 7.2 시스템 설명

이 화면·기능이 게임에서 어떻게 작동해야 하는지 관련 확정 DEC를 근거로 설명한다. 새로운
게임 규칙을 여기서 만들지 않는다 — 이미 확정된 규칙을 화면으로 어떻게 표현할지만 다룬다.

### 7.3 필요 요소

이 화면·기능이 표시하거나 조작해야 하는 정보·상태·입력을 나열한다. 각 요소가 어떤 확정
런타임 상태·DEC에서 나오는지 표시한다. 결정 로그에 없는 값은 만들지 않는다.

### 7.4 대안과 트레이드오프

배치·흐름·피드백 방식의 대안을 2~3개 텍스트로 제시한다. 좌표·픽셀·색상 코드처럼 아트 규격에
속하는 값(`DEC-ART-003` 대상)은 만들지 않는다. 상대적 배치("화면 하단 중앙", "선택 시
강조 표시")까지만 기술한다.

### 7.5 추천안

하나를 추천하고 이유를 한두 문장으로 설명한다.

### 7.6 확정 DEC 후보 문안

대상 DEC ID와 제목을 유지한 채 `상태: 확정`, `결정일`, `결정` 형식의 문안을 제시한다.
새 숫자 ID를 쓰지 않는다 — 원래 보류 항목의 ID를 그대로 확정으로 전환한다.

### 7.7 사람의 확인 질문

시스템에서 이미 확정한 것을 다시 묻지 않는다. 연출 톤·우선순위·생략 가능 여부처럼 사람이
결정해야 하는 질문만 최대 5개 제시한다.

### 7.8 단계 종료

다음 중 하나로 현재 상태를 표시한다.

- `초안 작성 중`
- `담당자 확인 대기`
- `단계 완료`

담당자의 명시적 승인 없이 `단계 완료`로 표시하거나 다음 항목으로 넘어가지 않는다.

## 8. 확정 시 처리 절차

한 항목이 확정되면 같은 작업 안에서 다음을 완료한다.

1. 결정 로그에서 해당 `DEC-UI-*` 항목을 보류에서 확정으로 전환한다 (같은 ID 유지).
2. `document-impact-map.csv`의 `DEC-UI-*` 행이 가리키는 시스템·UI/UX 기획서 13·15절을
   확인해 영향받는 구간만 최소 수정한다.
3. `npm run docs:check`로 자동 구조 검수를 수행한다.
4. 다음 항목으로 진행할지 담당자에게 확인한다.

전체 활성 DEC와 파생 문서의 의미 검수는 `DEC-PIPELINE-017`이 정한 시점(구조 변경, 프로토타입
구현 전, QA 후, 최종 기획서 작성 전)에 수행한다 — 매 항목마다 하지 않는다.

## 9. 시스템 질문에 답하는 방법

`밭두렁난투_콘텐츠_데이터_준비도_점검.md` 11절과 동일한 형식을 따른다.

1. **결론:** 현재 적용되는 규칙을 먼저 한두 문장으로 답한다.
2. **근거:** 폐기되지 않은 DEC ID와 상태를 제시한다.
3. **UI 영향:** 지금 다루는 화면·기능의 어떤 요소에 영향을 주는지 설명한다.
4. **보류 범위:** 아직 정하지 않은 값이면 관련 보류 DEC와 재검토 조건을 말한다.
5. **충돌 여부:** 과거 폐기 결정과 혼동하기 쉬우면 대체 결정까지 설명한다.

## 10. 시스템 기획 문제를 발견했을 때

UI/UX 작업 중 결정 로그의 불일치, 모호함, 규칙 누락 또는 구현 곤란을 발견하면 `AGENTS.md`
5절과 `밭두렁난투_콘텐츠_데이터_준비도_점검.md` 12절의 절차를 그대로 따른다 — 현재 항목
작업을 멈추고 문제 유형·관련 DEC·영향 범위·대안·추천안을 먼저 보고한다.

## 13. 전체 완료 조건

보류 `DEC-UI-*` 항목이 모두 확정돼도 다음을 통과하기 전에는 UI/UX 기획을 "완료"로
보고하지 않는다.

- 모든 `DEC-UI-*`가 확정 또는 명시적으로 재검토 조건이 남은 보류 상태
- 시스템·UI/UX 기획서 13절이 확정된 `DEC-UI-*` 내용과 일치
- `npm run docs:check` 차단 오류 0개
- 담당자의 최종 승인

실제 아트 규격은 `DEC-ART-003`에서 2026-08-07에 확정했다. 논리 에셋 ID 연결 CSV의 신설은
개발 담당의 스키마 작업이다.
