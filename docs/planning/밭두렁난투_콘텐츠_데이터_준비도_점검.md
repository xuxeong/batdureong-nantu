# 밭두렁난투 콘텐츠 데이터 준비도 및 AI 제작 가이드

- 갱신일: 2026-07-31
- 대상: 콘텐츠·레벨 기획 담당자와 콘텐츠 제작 보조 AI
- 저장소 최상위 규칙: `AGENTS.md`
- 함께 입력할 문서:
  1. `밭두렁난투_기획_결정로그_현재본.md`
  2. `밭두렁난투_시스템_UIUX_기획서_현재본.md`
  3. `밭두렁난투_콘텐츠_데이터_준비도_점검.md`

## 1. 이 문서를 사용하는 방법

저장소 루트에 `AGENTS.md`와 Claude Code용 `CLAUDE.md`를 둔다. AI는 `AGENTS.md`를 최상위 프로젝트 규칙으로 먼저 적용하고, 위 세 파일을 한꺼번에 읽는다. 저장소 규칙을 자동으로 읽지 않는 AI를 사용할 때는 `AGENTS.md`도 함께 제공한다.

이 문서는 AI가 세 기준 문서를 읽은 뒤 콘텐츠 테이블 제작 순서를 제시하고, 사람과 한 단계씩 CSV를 만드는 실행 지시문이다.

처음부터 31개 CSV를 한 번에 생성하지 않는다. AI는 먼저 의존성을 분석해 제작 순서를 제시하고, 담당자가 시작을 승인하면 한 단계의 시스템 설명과 CSV 초안만 제공한다. 담당자가 수정·확정하기 전에는 다음 단계로 넘어가지 않는다.

## 2. 문서 권한과 충돌 처리

AI는 다음 우선순위를 반드시 지킨다.

1. `AGENTS.md`
2. 결정 로그의 폐기되지 않은 최신 DEC
3. 시스템·UI/UX 기획서
4. 이 콘텐츠 데이터 준비도 및 AI 제작 가이드

규칙:

- `확정` DEC는 시스템 제약으로 사용한다.
- `보류` DEC는 재검토 조건이 충족된 콘텐츠 작업 항목으로만 다룬다.
- `폐기` DEC는 현재 규칙으로 사용하지 않고 변경 이력 설명에만 사용한다.
- 대체 결정이 있으면 대체 DEC를 현재 규칙으로 사용한다.
- 문서 사이에 충돌이 있으면 CSV 생성을 멈추고 충돌한 문장, DEC ID와 추천 해결안을 보고한다.
- 결정 로그에 없는 시스템 규칙을 재미나 편의를 이유로 임의 확정하지 않는다.
- 시스템 결정 변경이 필요하면 `DEC-PIPELINE-015`와 이 문서의 시스템 기획 문제 발견 절차를 따른다.

## 3. AI의 역할

AI는 다음 역할을 수행한다.

1. 세 문서의 현재 상태와 관련 DEC를 읽는다.
2. 콘텐츠 CSV의 의존성을 분석해 제작 순서를 제시한다.
3. 현재 단계의 시스템이 실제 플레이에서 어떻게 작동하는지 설명한다.
4. 해당 단계의 CSV 헤더, 필드 의미, 허용값과 참조 관계를 설명한다.
5. 프로토타입용 최소 콘텐츠 후보를 CSV 초안으로 제시한다.
6. 사람의 수정본을 마지막 초안 또는 승인본과 비교한다.
7. ID·상태·버전·참조를 정규화한 승인 후보와 변경 보고서를 만든다.
8. 사람이 명시적으로 승인한 뒤에만 다음 단계로 넘어간다.
9. 시스템 질문에는 결정 로그의 DEC ID와 상태를 근거로 답한다.
10. 사실·가정·제안·확인 필요를 섞지 않는다.

AI는 승인 콘텐츠나 자동 생성 런타임 JSON을 직접 덮어쓰지 않는다.

변경 가능한 게임 데이터는 코드에 하드코딩하지 않는다. 필수 데이터가 빠졌을 때 코드 기본값으로 보완하는 대신 차단 검수 오류로 보고하고, 프로토타입 임시값도 별도의 초안 또는 테스트용 데이터 파일에서 관리한다.

핵심 근거: `DEC-PIPELINE-002`, `DEC-PIPELINE-004`, `DEC-PIPELINE-007~016`.

## 4. 첫 응답에서 AI가 해야 하는 일

세 파일을 처음 받은 AI는 콘텐츠 CSV를 바로 만들지 말고 다음 내용을 먼저 출력한다.

### 4.1 문서 인식 결과

- 읽은 세 파일명
- 결정 로그의 기준일
- 확인한 확정·보류·폐기 결정 수
- 이름이 확정된 CSV 수
- 발견한 문서 충돌 또는 읽지 못한 범위

### 4.2 제작 순서 제안

각 단계에 대해 다음 열을 가진 표를 작성한다.

| 단계 | 만들 CSV | 먼저 필요한 데이터 | 관련 DEC | 이 단계의 완료 조건 |
|---|---|---|---|---|

아래 기본 순서를 출발점으로 사용한다. 더 나은 순서를 제안할 수 있지만, 참조 대상이 생성되기 전에 참조하는 CSV를 먼저 만들면 안 되며 변경 이유를 설명해야 한다.

### 4.3 첫 단계 시작 확인

AI는 추천 첫 단계와 그 이유를 한 문장으로 말하고 담당자에게 시작 승인을 요청한다. 승인 전에는 CSV 행을 대량 생성하지 않는다.

## 7. 단계별 AI 출력 형식

담당자가 한 단계를 시작하라고 승인하면 AI는 반드시 다음 순서로 답한다.

### 7.1 현재 단계

- 단계 번호와 이름
- 이번에 만드는 CSV
- 이미 승인된 선행 데이터
- 아직 없는 선행 데이터와 처리 방식

### 7.2 시스템 설명

콘텐츠 값이 게임에서 어떻게 사용되는지 비개발자도 이해할 수 있게 설명한다. 설명마다 근거 DEC를 붙인다.

예:

- `spawn_weight`는 확률 퍼센트가 아니라 현재 풀 안의 상대 가중치다. 근거: `DEC-CONTENT-003`.
- 자원 협상은 특정 작물을 요구하지 않고 총개수만 요구한다. 근거: `DEC-RESIDENT-050`.

### 7.3 필드 사전

각 CSV마다 다음 표를 작성한다.

| 필드 | 필수 여부 | 자료형 | 허용값·범위 | 참조 대상 | 기획자가 적을 내용 |
|---|---|---|---|---|---|

독립 콘텐츠는 공통 열을 먼저 사용한다.

- `id`
- `kind`
- `content_status`
- `content_version`
- `display_name`
- `design_intent`

연결 CSV에는 공통 열을 반복하지 않는다.

### 7.4 CSV 초안

- 파일별로 별도의 `csv` 코드 블록을 제공한다.
- 첫 줄은 확정된 헤더다.
- 프로토타입에서 연결 검증이 가능한 최소 후보 행을 제공한다.
- 아직 사람이 결정하지 않은 값은 작업용 초안에서만 `TBD`로 둔다.
- 신규 ID를 확실히 제안할 수 없으면 `AUTO`를 사용한다.
- 실제 존재하지 않는 참조 ID를 임의 생성하지 않는다.
- 후보를 만든 이유와 각 후보의 플레이 역할을 CSV 아래에서 설명한다.

### 7.5 자동 검수 보고

다음 형식으로 검사 결과를 표시한다.

| 심각도 | 파일·행·필드 | 문제 | 근거 DEC·규칙 | 최소 수정안 |
|---|---|---|---|---|

심각도:

- `차단`: 승인 또는 다음 단계 진행 불가
- `주의`: 진행 가능하지만 사람 검토 필요
- `제안`: 시스템 위반은 아니며 품질 개선 선택지

### 7.6 사람의 확인 질문

시스템에서 이미 확정한 것을 다시 묻지 않는다. 콘텐츠 의도·수량·밸런스처럼 사람이 결정해야 하는 질문만 최대 5개 제시한다.

### 7.7 단계 종료

AI는 다음 중 하나로 현재 상태를 표시한다.

- `초안 작성 중`
- `담당자 수정 대기`
- `승인 후보 검수 중`
- `담당자 승인 대기`
- `단계 완료`

담당자의 명시적 승인 없이 `단계 완료`로 표시하거나 다음 단계 CSV를 만들지 않는다.

## 8. 담당자가 CSV를 수정해 다시 줄 때

AI는 수정본을 즉시 승인본으로 덮어쓰지 않는다. 다음 순서로 처리한다.

1. 수정본의 인코딩·헤더·셀 값을 정규화한다.
2. 마지막 초안 또는 승인본과 비교한다.
3. 추가·삭제·변경 행을 찾는다.
4. 사람이 바꾼 콘텐츠 의도를 우선 보존한다.
5. ID·`kind`·상태·버전·참조·논리 에셋 ID를 정규화한다.
6. 연결하지 못한 값은 임의 연결하지 않고 오류 또는 `TBD`로 보고한다.
7. 승인 후보 CSV를 별도로 출력한다.
8. 변경 보고서와 검증 보고서를 출력한다.
9. 사람의 승인 후에만 승인 CSV로 확정한다.

연결 CSV가 바뀌면 `DEC-PIPELINE-011`에 따라 부모 콘텐츠를 `needs_review`로 보고하고 승인 시 부모 `content_version`을 증가시킨다.

## 9. ID·상태·버전 규칙

### ID

- 형식: `kind.고유_이름`
- 문자: 영문 소문자, 숫자, 밑줄, 마침표
- 저장소 전체에서 중복 금지
- 최초 승인 후 표시 이름이 바뀌어도 ID 자동 변경 금지
- 승인 ID 변경은 전체 참조를 확인하는 별도 이전 작업

### 상태

- `draft`
- `in_review`
- `approved`
- `needs_review`
- `retired`

게임은 마지막으로 검증을 통과한 `approved` 데이터만 사용한다.

### 버전

- 신규 승인 후보: `content_version` 1
- 승인된 의미가 변경되면 1 증가
- 정렬·인코딩·열 순서 정규화만으로는 증가하지 않음
- 연결 행의 변경은 지정된 부모 콘텐츠 버전에 귀속

핵심 근거: `DEC-CONTENT-001`, `DEC-PIPELINE-009~013`.

## 10. CSV 값 작성 규칙

- 작업용 CSV는 UTF-8 BOM 허용
- 승인 후보와 승인 CSV는 UTF-8 쉼표 구분 형식으로 정규화
- 불리언은 `true`, `false`
- 정수에는 단위·천 단위 쉼표·소수점 금지
- 실수의 소수점은 마침표
- 선택값이 없으면 빈 셀
- `null`, `N/A`, `없음`, `-`로 빈 값을 대신하지 않음
- `AUTO`, `TBD`는 작업용·승인 후보에서만 허용
- 승인 CSV에는 빈 필수값·`AUTO`·`TBD` 금지
- 셀 안 실제 줄바꿈 금지

핵심 근거: `DEC-PIPELINE-008`, `DEC-PIPELINE-013`.

## 11. 시스템 질문에 답하는 방법

담당자가 “왜 이 필드가 필요한가?”, “이 기능은 낮에도 가능한가?”, “협상 성공 조건은 무엇인가?”처럼 시스템을 질문하면 AI는 다음 형식으로 답한다.

### 답변 형식

1. **결론:** 현재 적용되는 규칙을 먼저 한두 문장으로 답한다.
2. **근거:** 폐기되지 않은 DEC ID와 상태를 제시한다.
3. **콘텐츠 영향:** 지금 작성 중인 CSV의 어떤 필드·행에 영향을 주는지 설명한다.
4. **보류 범위:** 아직 정하지 않은 값이면 관련 보류 DEC와 재검토 조건을 말한다.
5. **충돌 여부:** 과거 폐기 결정과 혼동하기 쉬우면 대체 결정까지 설명한다.

규칙:

- 결정 로그 문장을 인용할 때 의미를 바꾸지 않는다.
- 폐기 DEC만을 근거로 답하지 않는다.
- 로그에 답이 없으면 `결정되지 않음`이라고 말하고 임의로 확정하지 않는다.
- 새 결정이 필요하면 CSV를 수정하기 전에 영향받는 시스템·데이터·UI를 먼저 보고한다.

## 12. 시스템 기획 문제를 발견했을 때

콘텐츠·레벨 담당자는 작업 중 현재 결정이 실제 콘텐츠를 표현하지 못하거나 서로 충돌한다고 판단하면 시스템 기획 검토를 요청할 수 있다. 이때 AI는 콘텐츠 값을 억지로 맞추거나 임의 열을 추가하지 않고 현재 CSV 단계를 `시스템 결정 검토로 중단` 상태로 바꾼다.

### 12.1 문제로 분류하는 경우

- `불일치`: 두 개 이상의 활성 DEC 또는 기준 문서가 서로 다른 처리를 요구한다.
- `모호함`: 같은 문장을 여러 방식으로 구현하거나 콘텐츠에 적용할 수 있다.
- `규칙 누락`: 필요한 상태, 입력, 결과, 예외 또는 데이터 연결이 결정되지 않았다.
- `구현 곤란`: 현재 구조가 HTML 프로토타입 범위에서 구현 불가능하거나 위험이 지나치게 크다.
- `콘텐츠 충돌`: 확정된 필드·열거형·참조만으로 의도한 콘텐츠를 표현할 수 없다.

단순 밸런스 수치나 콘텐츠 이름 선택은 시스템 문제로 올리지 않고 현재 콘텐츠 단계에서 결정한다.

### 12.2 AI의 검토 순서

1. 현재 CSV 생성·수정과 승인 처리를 멈춘다.
2. 관련 확정·보류·폐기 DEC와 폐기 결정의 대체 연결을 확인한다.
3. 문제 유형과 문제가 재현되는 구체적인 콘텐츠 예를 제시한다.
4. 영향을 받는 시스템, UI/UX, CSV·필드·참조, 스키마, 코드와 에셋을 구분한다.
5. 변경하지 않을 때의 결과를 설명한다.
6. 가능한 대안, 장단점, 최소 변경안과 AI 추천안을 제시한다.
7. 프로젝트 책임자와 한 쟁점씩 대화하고 명시적 승인을 기다린다.

AI는 이 단계에서 결정 로그를 직접 바꾸지 않는다. 책임자가 `확정`, `수정 확정`, `폐기 후 대체`처럼 명시적으로 승인한 뒤에만 로그 반영 단계로 이동한다.

### 12.3 확정·보류·폐기 반영

- 새 확정 DEC는 `상태`, `결정일`, `결정`만 기록한다.
- 보류 DEC는 `상태`, `재검토 조건`만 기록한다.
- 과거에 확정된 결정을 폐기할 때는 기존 ID·제목·결정 원문을 보존하고 `상태`, `결정일`, `결정`, `폐기일`, `폐기 이유`, `대체 결정`을 기록한다.
- 의미가 바뀐 대체 규칙은 새 숫자 DEC ID로 작성한다.
- 확정 전 채택하지 않은 제안은 로그에 기록하지 않는다.
- 확정 DEC의 문구를 의미 변화 없이 고쳐야 해도 대상 ID, 이유와 바뀌는 문장을 먼저 알리고 승인을 받는다.

### 12.4 동기화·영향 검수·작업 재개

결정 반영과 같은 작업 안에서 다음을 수행한다.

1. 작업용 결정 로그와 사용자 공개용 현재본을 동기화한다.
2. `document-impact-map.csv`의 정확한 DEC ID 행을 먼저 찾고, 없으면 DEC 접두어 행으로 영향받는 문서와 절을 찾는다.
3. 현재 구조 설명이나 데이터 제작 절차가 바뀐 구간만 의미 검토하고 최소 범위로 수정한다.
4. 영향이 없는 문단은 다시 작성하거나 표현을 다듬지 않는다.
5. 파생 문서 전체에는 DEC ID·참조·상태 구조·제목·CSV 목록·코드 블록·예상 밖의 원문 변경·사본 일치 자동 검수만 수행한다.
6. 영향을 받은 승인 콘텐츠와 연결 CSV를 `needs_review`로 전환할지 보고한다.
7. 필드·자료형·열거형·참조 방식이 바뀌면 스키마 버전, 기존 CSV 변환과 검증·생성 과정의 영향을 보고한다.
8. 구조·스키마 변경이나 지정된 마일스톤이면 전체 의미 검수를 수행한다.
9. 검증 완료 후 중단한 CSV 단계와 마지막 안전한 데이터 상태를 알리고 작업 재개 승인을 요청한다.

핵심 근거: `DEC-PIPELINE-015`, `DEC-PIPELINE-017`.

## 13. AI에게 그대로 전달할 시작 프롬프트

```text
너는 밭두렁난투의 콘텐츠·레벨 데이터 기획 보조자이자 검수자다.

저장소 루트의 AGENTS.md를 먼저 끝까지 읽고 최상위 프로젝트 규칙으로 적용하라.

첨부한 세 문서를 모두 읽어라.
1. 밭두렁난투_기획_결정로그_현재본.md
2. 밭두렁난투_시스템_UIUX_기획서_현재본.md
3. 밭두렁난투_콘텐츠_데이터_준비도_점검.md

[권한]
- AGENTS.md는 역할, 문서 권한, 승인 절차와 변경 안전 규칙의 단일 원본이다.
- 결정 로그의 폐기되지 않은 최신 DEC가 단일 원본이다.
- 시스템 기획서는 현재 구조를 이해하기 위한 설명서다.
- 콘텐츠 준비도 문서는 작업 순서와 출력 형식을 지시한다.
- 문서가 충돌하면 CSV를 만들지 말고 충돌 위치와 DEC ID를 보고한다.
- 변경 가능한 게임 데이터는 코드에 하드코딩하지 않고 승인 데이터에서 공급한다. 누락값을 코드 기본값으로 숨기지 않는다.

[첫 작업]
1. 읽은 문서와 검사 범위를 보고한다.
2. 확정·보류·폐기 DEC 수와 이름이 확정된 CSV 수를 확인한다.
3. CSV 사이의 참조 의존성을 분석한다.
4. 콘텐츠 테이블 제작 순서를 표로 제안한다.
5. 각 단계의 선행 데이터, 관련 DEC와 완료 조건을 적는다.
6. 아직 CSV 초안을 만들지 말고 추천 첫 단계의 시작 승인을 요청한다.

[단계 진행]
- 내가 단계를 시작하라고 하면 해당 단계의 시스템 작동을 DEC 근거와 함께 설명한다.
- 필드 사전과 프로토타입 최소 CSV 초안을 파일별 csv 코드 블록으로 제공한다.
- 사실, 가정, 제안, 확인 필요를 구분한다.
- 내가 수정한 CSV를 다시 주면 원본과 비교해 정규화된 승인 후보와 변경 보고서를 제공한다.
- 내가 명시적으로 승인하기 전에는 다음 단계로 넘어가지 않는다.

[질문 응답]
- 시스템 질문은 결정 로그의 폐기되지 않은 DEC를 참조해 답한다.
- 보류 사항은 확정값처럼 만들지 않는다.
- 로그에 없는 규칙은 결정되지 않았다고 보고한다.
- 모순, 모호함, 규칙 누락, 구현 곤란 또는 콘텐츠 충돌을 발견하면 현재 CSV 작업을 멈추고 콘텐츠 준비도 문서의 시스템 기획 문제 발견 절차로 전환한다.
```

## 15. 수정본 검수 프롬프트

```text
아래는 콘텐츠 담당자가 수정한 작업용 CSV다.

[입력]
- 기준 세 문서
- 마지막 초안 또는 승인본
- 담당자 수정본

[작업]
1. 인코딩·헤더·값 표현을 정규화한다.
2. 추가·삭제·변경 행을 비교한다.
3. 담당자가 수정한 콘텐츠 의도를 보존한다.
4. ID, kind, content_status, content_version과 참조를 검사한다.
5. 연결 CSV 변경이 부모 버전에 미치는 영향을 계산한다.
6. 존재하지 않거나 승인되지 않은 참조를 보고한다.
7. 정규화된 승인 후보 CSV를 파일별 csv 코드 블록으로 제공한다.
8. 변경 보고서와 차단·주의·제안 검수표를 제공한다.

AI가 스스로 approved 상태를 확정하거나 기존 승인본을 덮어쓰지 마라.
```

## 16. 시스템 기획 검토 프롬프트

```text
현재 콘텐츠·레벨 작업 중 시스템 기획 문제를 발견했다.

[입력]

- 마지막 검증 통과 승인본

너는 AI 활용 게임 제작에 능한 게임 디자이너이자 개발자다.

[작업]
1. 현재 CSV 생성·수정과 승인 처리를 멈춘다.

4. 문제가 되는 실제 콘텐츠 사례를 설명한다.

- 의미를 유지하는 문구 수정도 대상 ID, 이유와 바뀌는 문장을 먼저 알리고 승인받는다.

- 상태별 허용 항목과 제목 구조는 AGENTS.md를 따른다.

- 영향을 받은 승인 콘텐츠, 스키마 버전과 변환 필요성을 보고한 뒤 중단했던 단계의 재개 승인을 요청한다.
```

## 17. 전체 완료 조건

12단계가 모두 끝나도 다음 조건을 통과하기 전에는 런타임 데이터 생성을 요청하지 않는다.

- 모든 독립 콘텐츠 ID가 저장소 전체에서 고유
- 모든 `kind`와 ID 접두어 일치
- 승인 데이터의 필수값·`AUTO`·`TBD` 검사 통과
- 모든 참조가 존재하고 올바른 종류와 승인 상태
- 연결 CSV의 복합 키 중복 없음
- 주민마다 프로토타입 사연 정확히 하나
- 성격 프로필마다 세 전투 전 선택 결과 존재
- 사연마다 기본·핵심 정보와 두 시작 대사 존재
- 선택지별 도달 가능한 모든 결과 반응 존재
- 모든 작물에 기본 레시피 존재
- 모든 무기·회복 아이템에 정확히 하나의 결과 레시피 존재
- 보상 묶음의 자원 참조와 수량 유효
- 런 일정의 일차 연속성·마지막 습격·주민 중복 검사 통과
- 공포도 구간의 연속성·기본 엔딩·우선순위 검사 통과
- 실제 콘텐츠 행에 대한 차단 오류 0개
- 콘텐츠 담당자의 최종 승인

검증을 통과한 승인 CSV만 런타임 JSON 생성 입력으로 사용한다.
