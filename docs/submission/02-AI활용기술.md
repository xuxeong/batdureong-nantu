## 3. 구조 — 저장소 자체를 AI 지시서로 사용

이 프로젝트의 핵심은 **AI가 매번 같은 규칙과 근거를 읽고 작업하도록 저장소를 설계한 것**이다.

| 파일 | 역할 |
|---|---|
| `AGENTS.md` | 모든 AI가 먼저 적용하는 최상위 규칙. 역할, 문서 권한, 승인 절차, 변경 안전 규칙 |
| `CLAUDE.md` | Claude Code 진입점. `@AGENTS.md`를 임포트해 규칙을 중복 정의하지 않음 |
| `docs/planning/…결정로그…` | 확정·보류·폐기 결정(DEC)의 단일 원본 |
| `docs/governance/document-impact-map.csv` | DEC가 바뀔 때 영향을 받는 문서·절을 기계적으로 찾는 매핑 |
| `schema/tables/` | 콘텐츠 CSV의 필드·자료형·참조 정의. AI가 임의 열을 만들지 못하게 막는 제약 |

## 4. 콘텐츠 제작 파이프라인

```
콘텐츠 원본·제약 규칙 → AI 초안 → 담당자 검토 → 승인 콘텐츠 → 자동 검증 → 런타임 데이터
```

근거: `DEC-PIPELINE-004`, `DEC-PIPELINE-007`

- AI는 **초안만** 작성한다. 승인 콘텐츠와 런타임 데이터를 직접 덮어쓸 수 없다.
- 담당자가 엑셀에서 CSV를 수정하면 AI가 마지막 승인본과 비교해 **변경 보고서**를 만든다.
- 사람이 명시적으로 승인한 데이터만 검증과 런타임 생성의 입력이 된다.

## 6. 런타임 LLM — 엔딩 기록문

근거: `DEC-CONTENT-011`, `DEC-RESIDENT-001`

**LLM은 엔딩 기록문 작성에만 사용한다.** 주민 사연·대사·선택 반응·판정·게임 상태 변경에는
관여하지 않는다. 시스템이 엔딩 ID·제목·결과를 먼저 확정한 뒤, 플레이어가 **실제로 확인한 사실만**
LLM에 전달한다.

- 플레이어 이름은 명령이 아닌 인용된 데이터로 처리한다 (프롬프트 인젝션 차단)
- 출력은 `record_text` 하나만 가진 JSON으로 제한하고 구조·길이·형식을 검사한다
- 실패 시 1회 재시도 후 고정 폴백 기록문을 사용하며, 게임 완료를 막지 않는다
