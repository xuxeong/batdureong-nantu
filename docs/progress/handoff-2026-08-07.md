## 2. P0 — **UI 에셋 16장이 파일만 있고 코드가 쓸 수 없다**

**8/7 에 찾았다. 아무도 안 적어둔 자리다.**

전성민이 준 A4 조립 지시는 이렇다.

```
대사창       panel_border + panel_texture 9-slice
발화자 이름판  button_normal
일반 선택지    button_normal
비활성 선택지  button_disabled
선택지 외곽    choice_balloon.png
```

그런데 `schema/enums.json` 의 `ui_system_asset_id` 고정 목록은 **13개뿐**이고
`panel_border`·`panel_texture`·`button_*` 이 전부 없다. `src/render/assets.ts` 는
목록에 없는 ID 를 쓰면 **의도적으로 throw 한다** (`DEC-ART-001` — 새 ID 추가는
데이터 행 추가가 아니라 스키마 변경).

즉 **CSS 만 고쳐서는 안 붙는다. 스키마 변경이 선행돼야 한다.**
전성민이 8/7 에 *"대사창과 choice_balloon 에셋 모두 제대로 적용되지 않은 것으로
보인다"* 고 한 것의 원인이 이것이다. 목록에 있는 `choice_balloon` 만 붙었다.

`assets/final/ui/` 28장 중 목록에 없어 코드가 못 쓰는 16장:

```
panel_border   panel_texture                       A4 대사창
button_normal  button_pressed  button_disabled     A4 이름판·선택지 · 정비 허브 버튼
item_slot      item_slot_badge                     보관함 칸과 수량 배지 (14.8)

shutter_left   shutter_right                       ← 인계 3-3 「셔터 연출」의 답이 이미 파일로 와 있다
step_minus     step_plus                           수량 조절
```

**`shutter_left`·`shutter_right` 는 따로 본다.** 8/6 인계 3-3 이 *"「셔터 연출」이라
부르는데 실제로는 어두운 판이 즉시 나타날 뿐이고 아무도 안 적어둔 누락"* 으로
올려 둔 항목인데, **그림이 이미 와 있다.** 방향·시간·나갈 때도 연출인지는 여전히
전성민 결정이지만 "이미지를 쓸지" 는 파일이 답했다.

목록에 있는데 파일이 없는 것은 `resident_hp_gauge` 하나다. `close_button` 은
파일이 왔는데 `layout.css:1283`·`maintenance-hub.ts:297` 주석이 아직
*"B단계라 파일이 없어 글자 버튼"* 이라고 말한다. `enums.json` 의 `$comment` 도 같다.

### 4-1. 캐릭터 모션이 `DEC-ART-001` 과 충돌한다

8/6 밤 대화에서 셋이 나왔다.

- *"낫을 따로 안 주고 붙은 채로 주고, 휘두를 때 휘두르는 스프라이트로 교체 0.2초"*
- *"주민들도 공격할 때 낫 휘두르는 것처럼 스프라이트가 교체되는 걸로"*
- *"정면 + 낫 휘두름 → 좌·우 → 걷는 애니메이션 순으로 추가"*

**셋 다 `DEC-ART-001` 의 프레임 애니메이션·스프라이트 시트 금지와 정면 충돌한다.**
2프레임이어도 프레임 애니메이션이다. 전성민의 8/7 회신에는 이 건이 없다.

지금 상태로는 근거가 없어 구현할 수 없다. **폐기·대체를 할지 8/8 회의에서
정해야 한다.** 안 정하면 8/7 플레이 테스트에서 나온
*"다 정면만 있어서 캐릭터가 동동 떠다닌다"* 는 못 고친다.

같은 문장이 *"움직임은 코드가 위치·크기·투명도로 표현한다"* 로 열어 둔 범위는
그대로 쓸 수 있다 — 걷기 흔들림, 피격 깜빡임이 그 안이다.
