# 작업 로그 — 최수정 (개발)

**Git 커밋에 남지 않는 것만 적는다.** 무엇을 바꿨는지는 `PROGRESS.md`와 diff에 이미 있다.

작성 형식 (해당 없으면 생략):

```
## YYYY-MM-DD 제목

**한 일** — 한두 줄

**왜 이렇게 했나** — 어떤 대안을 검토했고 왜 접었나

**AI가 잘못한 것** — 무엇을 어떻게 잡았나

**막힌 것** — 결정로그에 답이 없는 것. 기획 책임자에게 올릴 목록
```

`AI가 잘못한 것`과 `막힌 것`이 제일 중요하다. 8/8 제출 자료의
「AI 활용 기술 문서」와 「팀원 롤 기술서」를 쓸 때 이 기록이 그대로 재료가 된다.
일주일 뒤에 기억으로 복원하려 하면 대부분 잃어버린다.

이 파일은 개인 전용이라 다른 사람과 충돌하지 않는다.

**AI가 잘못한 것**

스키마 31종을 만들면서 **DEC에 없는 문장 734개를 내가 지어냈다.** 필드마다 "기획자가
적을 내용"을 쓴 `guide` 154개, DEC 문장을 내 표현으로 요약한 `description` 295개,
결정로그가 "쓰지 않는다"고만 한 기능을 내가 열 이름으로 바꾼 `excluded_fields` 168개다.

문제는 이게 스키마 파일 안에 있으면 **기획 책임자가 정한 것처럼 읽힌다**는 점이다.
`farming_duration_seconds`에 "해커톤 심사용이면 짧은 편이 안전하다"고 적었는데,
이건 결정로그 어디에도 없는 내 판단이었다.

그리고 검증 규칙 2개(`wildlife.used_by_spawn_profile`,
`personality_profile.referenced_by_resident`)는 해당 DEC의 검증 목록에 아예 없는데
내가 추가했다.

전부 걷어냈다. 스키마에는 구조(필드명·자료형·범위·참조)와 근거 DEC ID만 남겼고,

줄이는 식으로 내가 표현을 다듬어 놓은 상태였다.

**세운 기준**: 파일이 무엇이냐가 아니라 **내용이 누구 것이냐**로 판단한다.
게임 규칙·필드 정의·판정 방식은 기획 문서 소유라 인용만 하고, 저장소 구조·npm 명령·

**한 일**
`PROGRESS.md` 갱신과 검증을 GitHub Actions로 옮기고, `CLAUDE.md`에 세션 로그를
묻지 말고 쓰라는 규칙을 넣었다.

  갱신하지 않았다"고 내가 직접 적어놨는데도 그 다음 커밋에서 또 안 했다. 규칙을
  글로 더 강하게 쓰는 대신 실행 주체를 사람에서 CI로 바꿨다.
- **`if: github.actor != 'github-actions[bot]'`와 `[skip ci]`를 둘 다 걸었다.**
  봇이 만든 커밋이 다시 push 이벤트를 일으켜 무한히 도는 것을 막는다. 둘 중 하나만
  있어도 대개 막히지만 워크플로 트리거를 나중에 바꿀 때 한쪽이 무력해진다.
- **`fetch-depth: 0`이 필요하다.** `tools/progress.mjs`가 전체 커밋 이력을 읽는데
  Actions 기본 체크아웃은 얕은 클론이라 최근 커밋만 나온다.
- **세션 로그는 자동화할 수 없어서 규칙으로 남겼다.** "왜 그렇게 했나"와 "AI가 뭘
  잘못했나"는 diff에서 뽑아낼 수 없다. 대신 `CLAUDE.md`에 **묻지 말고** 쓰라고
  적고, 빠뜨리기 쉬운 조건 4가지를 나열했다. 확인을 받으려 하면 그 순간 안 쓰게 된다.

**AI가 잘못한 것**

오늘 "PROGRESS.md가 최신이 아니다"라는 지적을 받고 처음엔 CI가 실패했다고 봤다.
실제로는 CI가 정상이었고 봇 커밋(`a541c74`)이 원격에만 있었다. 로컬에서 `git fetch`를
안 해서 안 보였을 뿐이다. **로컬 상태를 원격과 같다고 가정하고 진단을 시작했다.**
하마터면 같은 내용을 로컬에서 다시 생성해 중복 커밋을 만들 뻔했다.

자동 생성 파일을 CI가 커밋하는 구조에서는 **작업 시작 전에 `git pull`이 필수**다.
안 하면 로컬 재생성분과 봇 커밋이 충돌한다.

**막힌 것**

없음. 배포·LLM 사용 여부는 7/31 항목 그대로 미확정.

**왜 이렇게 했나**

- **일정을 검수했더니 일정이 문제가 아니라 입력물이 없었다.** 초안은 8/3에 대화 UI, 8/4에 엔딩 판정을 배치했는데 `dialogue_choices`·`endings` CSV가 초안조차 없었고 `data/approved/`는 비어 있었다. 사람 배치를 조정할 게 아니라 선행 조건을 먼저 드러내야 했다.
- **분담 기준을 "난이도"가 아니라 "틀렸을 때 어떻게 알아채는가"로 잡았다.** 코드는 대부분 Claude Code가 쓰니 사람이 나눌 것은 검증 방식이다. 화면에 결과가 보이는 영역(UI·재배·상점)은 실행해보면 알 수 있어 병렬로 돌려도 안전하고, 하드코딩·부분 반영처럼 실행해도 안 보이는 영역은 사람이 코드를 읽어야 한다.
- **범위를 자르지 않는 대신 컷 트리거를 미리 정했다.** 8/5까지 전 기능이 목표라 지금 뺄 수는 없지만, 8/4 22시·8/5 18시에 무엇을 포기할지 당일에 논의하면 그 시간에 통합이 안 끝난다.
- **완주 경로 체크리스트(11-1)를 따로 만들었다.** 4절은 "하기로 한 일" 목록이라 아무도 적지 않은 작업은 못 잡는다. 마지막 날 터지는 건 미룬 작업이 아니라 적어두지 않은 작업이다. 화면 단위 31줄로 펴 보니 8/5에 7줄이 몰려 있는 게 드러났다.
- **로컬 LLM 모킹 분기를 만들자는 제안을 접었다.** 로컬만 재시도를 건너뛰면 프로덕션에서 처음 도는 경로가 생긴다. `.env.example`이 이미 "키가 비면 폴백이 정상 경로"라고 적어 두었으므로 로컬 404도 같은 실패로 취급하면 분기 없이 해결된다. 실제 LLM 경로 확인은 `vercel dev`로 한다.
- **UI 레이아웃 수치는 CSV로 빼지 않기로 했다.** 기획자가 UI 위치를 사진으로 주면 조정해야 하는데, 화면 배율·좌표는 표현이지 게임 데이터가 아니다. `layout.css`의 CSS 변수 한 파일에 모으면 TS를 안 건드리고 조정할 수 있어 담당자 간 충돌도 없다.
- **develop 브랜치는 충돌 방지 목적이 아니라고 정리했다.** 두 사람이 develop 하나에 커밋하면 충돌 양상은 같다. 실익은 main을 시연 가능한 상태로 고정하는 것(8/8 촬영)이라 그 목적에 맞춰 규칙을 썼다.

**AI가 잘못한 것**
