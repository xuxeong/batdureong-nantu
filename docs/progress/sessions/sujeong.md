# 작업 로그 — 최수정 (개발)

**Git 커밋에 남지 않는 것만 적는다.** 무엇을 바꿨는지는 `PROGRESS.md`와 diff에 이미 있다.

작성 형식 (해당 없으면 생략):

```
## YYYY-MM-DD 제목

**한 일** — 한두 줄

**왜 이렇게 했나** — 어떤 대안을 검토했고 왜 접었나

**AI가 잘못한 것** — 무엇을 어떻게 잡았나

**막힌 것** — 결정로그에 답이 없는 것. 기획 책임자에게 올릴 목록
```

`AI가 잘못한 것`과 `막힌 것`이 제일 중요하다. 8/8 제출 자료의
「AI 활용 기술 문서」와 「팀원 롤 기술서」를 쓸 때 이 기록이 그대로 재료가 된다.
일주일 뒤에 기억으로 복원하려 하면 대부분 잃어버린다.

이 파일은 개인 전용이라 다른 사람과 충돌하지 않는다.

스키마 31종을 만들면서 **DEC에 없는 문장 734개를 내가 지어냈다.** 필드마다 "기획자가

문제는 이게 스키마 파일 안에 있으면 **기획 책임자가 정한 것처럼 읽힌다**는 점이다.

이건 결정로그 어디에도 없는 내 판단이었다.

그리고 검증 규칙 2개(`wildlife.used_by_spawn_profile`,
`personality_profile.referenced_by_resident`)는 해당 DEC의 검증 목록에 아예 없는데
내가 추가했다.

전부 걷어냈다. 스키마에는 구조(필드명·자료형·범위·참조)와 근거 DEC ID만 남겼고,

**세운 기준**: 파일이 무엇이냐가 아니라 **내용이 누구 것이냐**로 판단한다.
게임 규칙·필드 정의·판정 방식은 기획 문서 소유라 인용만 하고, 저장소 구조·npm 명령·

**한 일**

  글로 더 강하게 쓰는 대신 실행 주체를 사람에서 CI로 바꿨다.
- **`if: github.actor != 'github-actions[bot]'`와 `[skip ci]`를 둘 다 걸었다.**
  봇이 만든 커밋이 다시 push 이벤트를 일으켜 무한히 도는 것을 막는다. 둘 중 하나만
  있어도 대개 막히지만 워크플로 트리거를 나중에 바꿀 때 한쪽이 무력해진다.
- **`fetch-depth: 0`이 필요하다.** `tools/progress.mjs`가 전체 커밋 이력을 읽는데
  Actions 기본 체크아웃은 얕은 클론이라 최근 커밋만 나온다.
- **세션 로그는 자동화할 수 없어서 규칙으로 남겼다.** "왜 그렇게 했나"와 "AI가 뭘
  잘못했나"는 diff에서 뽑아낼 수 없다. 대신 `CLAUDE.md`에 **묻지 말고** 쓰라고
  적고, 빠뜨리기 쉬운 조건 4가지를 나열했다. 확인을 받으려 하면 그 순간 안 쓰게 된다.

**AI가 잘못한 것**

오늘 "PROGRESS.md가 최신이 아니다"라는 지적을 받고 처음엔 CI가 실패했다고 봤다.
실제로는 CI가 정상이었고 봇 커밋(`a541c74`)이 원격에만 있었다. 로컬에서 `git fetch`를
안 해서 안 보였을 뿐이다. **로컬 상태를 원격과 같다고 가정하고 진단을 시작했다.**
하마터면 같은 내용을 로컬에서 다시 생성해 중복 커밋을 만들 뻔했다.

자동 생성 파일을 CI가 커밋하는 구조에서는 **작업 시작 전에 `git pull`이 필수**다.
안 하면 로컬 재생성분과 봇 커밋이 충돌한다.

**막힌 것**

없음. 배포·LLM 사용 여부는 7/31 항목 그대로 미확정.

`resolution.ts` 로 최종 결과·관계·공포도·보상을 원자적으로 처리하게 하고 `main.ts` 에
붙였다. 투항 선택 개발 통로를 놓아 최종 결과 다섯 개를 전부 플레이로 확인했다.

**왜 이렇게 했나**

- **`DEC-RESIDENT-052` 의 상태 조합을 표 하나로 모았다.** 처치·투항·대화 해결이 각자
  주민 상태를 고치면 "처치했는데 관계가 단절이 아닌" 조합이 만들어지고, 엔딩 판정이
  그걸 그대로 읽는다. 조우를 끝내는 경로를 `finishEncounter()` 하나로 뒀다.
- **공포도는 자리만 만들고 값을 비웠다.** `DEC-RESIDENT-048` 이 보류라 증가량이 승인
  CSV 에 없다. 통째로 막을 수도 있었지만 그러면 8/5 완주가 048 하나에 걸린다.
  `fearIncrements` 가 null 이면 공포도만 멈추고 나머지는 진행하며 개발 빌드에 경고를
  남긴다. **임시 기본값을 넣지 않은 것이 핵심이다** — 넣었으면 아무도 048 을 다시 안 본다.
- **투항 통로를 여섯 번째 임시 통로로 추가했다.** 통로를 늘리는 건 부담이지만, 투항
  3선택지가 최종 결과 다섯 중 셋과 보상 경로 전체로 가는 유일한 문이라 김민주의 모달을
  기다리면 오늘 아무것도 확인할 수 없었다.

**AI가 잘못한 것**

- **`canAppearAsHostile()` 을 만들고 테스트까지 하고 부르는 데를 안 만들었다.**
  담당자가 "1,2번 다 한 거야?" 라고 묻지 않았으면 그대로 완료로 넘어갔다.
  **11-2 에 "만든 것을 배선하지 않고 완료로 보고하는 일이 네 번 반복됐다" 고 적어 둔
  바로 그 항목이다.** 적어 두는 것과 안 하는 것은 별개였다.
- **처치 처리를 두 군데 뒀다.** 투사체·지속 피해는 `combat.update()` 안에서, 낫 직접
  명중은 `swingSickle()` 이 그 자리에서 돌려준다. `updateRaid` 만 고치고 `onSickle` 은
  야생동물만 지우게 뒀더니 **낫으로 죽였을 때만** 조우가 안 끝났다. 8/3 에 대상 선택이
  두 군데라 낫이 아무도 못 때렸던 것과 **같은 구조를 처치 쪽에서 반복**했다.
  그때 세션 로그에 "대상 선택이 두 군데 있으면 반드시 한쪽이 틀린다" 고 써 놓고도 그랬다.
- **개발 통로 가드를 `inputOwner()` 로 짰다.** 콘솔로 전환하면 창이 포커스를 잃어 자동
  일시정지가 걸리고(`DEC-UI-022`) 일시정지는 항상 최상위라(`DEC-UI-026`) 100% 막힌다.
  **내가 구현한 두 규칙이 만나서 생기는 결과를 예측하지 못했다.**
- **개발 통로가 흐름이 금지한 상태를 만들어 냈다.** `enterFieldPreview()` 가 `run_failed`
  위에 필드를 다시 띄워서 체력 0인 플레이어가 계속 싸웠다. 화면 전환으로만 막고 있어서
  화면을 우회하는 경로에 그대로 뚫렸다. 실패 여부를 상태로 판단하도록 바꿨다.

**막힌 것**

- `DEC-RESIDENT-048` 공포도 증가량. 메시지로 올렸고 답 대기 중이다.

## 2026-08-05 새벽 엔딩 판정과 LLM 연결 — 그리고 흐름 입력을 또 안 보냈다

**한 일**
엔딩 판정(`ending.ts`, 테스트 14개), `fear_increments` 스키마, 프롬프트 원본 2종 신설,
`api/ending.ts`·`api/journal.ts`·`src/llm/` 로 기록문 생성과 폴백까지.

**왜 이렇게 했나**

- **폴백을 기본값이 아니라 실패의 결과로 만들었다.** 엔딩 판정이 후보를 못 찾거나 같은
  우선순위가 겹치면 전역 폴백으로 가되 `fallbackReason` 을 담아 콘솔에 남긴다. 조용히
  폴백으로 떨어지면 **콘텐츠 구멍이 정상 동작처럼 보인다.** 같은 우선순위에서 하나를
  임의로 고르지 않는 이유도 같다 — 같은 플레이가 다른 엔딩을 낼 수 있다.
- **규격을 어긴 LLM 응답을 다듬어 쓰지 않는다.** 길이 초과나 마크다운이 오면 실패로
  돌리고 승인된 폴백 문장을 쓴다. 다듬으면 무엇이 승인된 문장인지 흐려지고, 어긴
  사실 자체가 기록에 남지 않는다.
- **기록문 요청을 기다리지 않는다.** 엔딩을 확정해 런 결과에 저장한 **뒤에** 비동기로
  부르고 응답이 오면 폴백 문장을 대체한다. `DEC-CONTENT-011` 의 "LLM 요청이 엔딩
  진행을 막지 않는다" 를 구조로 지키는 방법이다.
- **내부 타입을 CSV 키와 통일했다.** 기획 회신은 짧은 키를 두고 읽을 때 매핑하라는
  것이었는데, 매핑 표를 두면 같은 행동을 가리키는 이름이 `resolution.ts` 안에서만 두
  벌이 된다. 회신이 막으려던 것과 같은 문제라 통일하는 쪽을 골랐고 그렇게 보고했다.

**AI가 잘못한 것**

- **버스 이벤트와 흐름 입력을 또 헷갈렸다.** `encounter_finished` 가 `flow.ts` 에
  정의돼 있는데 보내는 곳이 없어서, 조우가 끝나도 화면이 `raid` 에 남고 조우 결과 →
  엔딩 경로가 통째로 죽어 있었다. **엔딩 판정은 되는데 엔딩 화면에 도달하지 못했다.**
  체력 0에도 계속 움직였던 것과 같은 구조이고, 그때 `failRunIfDead` 주석에 "이벤트만
  쏘면 안 된다" 고 적어 둔 바로 그 파일에서 반복했다. 담당자가 "제대로 한 거 맞냐"고
  다시 묻지 않았으면 못 찾았다.
- **문서 중복을 만들었다.** pull 로 받은 커밋 메시지에 "기획 문서 갱신 완료" 라고
  적혀 있는 걸 읽고도 문서를 안 열어 보고, 전성민이 이미 넣은 CSV 목록 줄을 다른
  분류로 한 번 더 넣었다. `checkCsvList` 가 Set 으로 비교해서 자동 검수는 통과한다 —
  **자동 검수가 구조적으로 못 잡는 종류의 실수였다.**
- **개발 통로 가드를 두 규칙의 상호작용을 생각하지 않고 짰다.** 포커스 이탈 자동
  일시정지(`DEC-UI-022`)와 일시정지 최상위(`DEC-UI-026`)는 둘 다 내가 구현했는데,
  콘솔에서 부르는 통로가 그 둘 때문에 100% 막힌다는 걸 예측하지 못했다.

**막힌 것**

- `api/` 두 개를 nodejs 런타임으로 뒀다. 프롬프트 원본을 파일에서 읽어야 해서인데
  `health.ts` 주석이 nodejs 에서 Response 반환이 무한 로딩이 됐다고 적어 뒀다.
  **배포에서 확인이 필요하다.**
- LLM 키 주체가 정해지지 않았다. 키가 없으면 폴백이 정상 경로라 완주는 되지만
  8/8 촬영에서 생성을 보여주려면 팀이 정해야 한다.

## 2026-08-05 배포에서 네 번 틀렸다 — 로컬에서 확인할 수 있는 것들이었다

**한 일**
엔딩 기록문 API 가 프리뷰에서 죽는 것을 네 번에 걸쳐 고쳤다. 마지막으로 200 응답과
폴백 동작을 배포에서 확인했다.

**무엇이 원인이었나**

| 시도 | 결과 |
|---|---|
| `vercel.json` 에 `includeFiles` 추가 | **원인 아님.** 내 핸들러의 500 이 아니라 플랫폼 오류였는데 그걸 구분 안 하고 짐작으로 갔다 |
| `nodejs` 런타임 | 원인. edge 에 파일 시스템이 없어서 골랐는데 Node 런타임은 표준 Response 반환이 죽는다 |
| import 의 `.ts` 확장자 | 원인. `src/` 는 Vite 가 처리하지만 `api/` 는 Vercel 의 번들러가 따로 묶는다 |
| `@anthropic-ai/sdk` | 원인. edge 번들에 `node:fs`·`node:path` 를 끌고 들어온다 |

**AI가 잘못한 것**

- **`health.ts` 주석에 이미 답이 있었는데 읽고도 무시했다.** "Vercel 의 Node 런타임은
  기본 export 를 (req, res) 로 취급한다 … **실제로 겪었다**" 가 그 파일 머리에 적혀
  있다. 파일을 읽어야 한다는 이유로 그 경고를 넘겼고, 그래서 팀이 이미 한 번 낸
  사고를 그대로 재현했다. **저장소가 남긴 경고를 무시한 것이 오늘만 세 번째다**
  (보류 주석, 조건부 주석, 이번 것).
- **"로컬에서 못 밟는다"를 추측해도 된다는 뜻으로 썼다.** 뒤의 셋은 전부 로컬에서
  확인할 수 있는 조건이었다 — `api/` 안에 `node:` 내장 모듈이 있는가, `.ts` 확장자가
  있는가, 의존성이 무엇을 끌어오는가. 배포 로그를 받고서야 하나씩 알았다.
  **밟을 수 없는 환경일수록 제약을 먼저 목록으로 만들고 시작해야 했다.**
- **네 번 중 첫 번째는 원인 진단 없이 push 했다.** 500 과 `FUNCTION_INVOCATION_FAILED`
  는 다른 층위인데 구분하지 않았다. 응답 본문을 확인했으면 한 번에 알았다.

**왜 이렇게 고쳤나**

- **SDK 를 걷어내고 `fetch` 로 갔다.** 런타임을 nodejs 로 바꾸면 SDK 를 쓸 수 있지만
  그쪽은 `health.ts` 가 경고한 길이다. 우리가 쓰는 건 메시지 한 번 보내고 텍스트
  하나 받는 것뿐이라 표준 `fetch` 로 충분하고, 팀규칙 7절이 `api/` 에 요구하는 것도
  표준 웹 Request/Response 다. **의존성을 지웠으니 다시 딸려 올 경로가 없다.**
- **프롬프트를 빌드 시점에 굽는다.** edge 에 파일 시스템이 없다고 프롬프트 문장을
  코드에 복사하면 `DEC-PIPELINE-012` 위반이다. `.md` 를 원본으로 두고 생성물만
  `api/_prompts.ts` 로 만든다 — `generated/runtime/` 과 같은 취급이라 커밋하지 않는다.

**얻은 것**

프리뷰에 키가 없어서 **LLM 실패 경로가 실제 배포에서 검증됐다.** 500 이 나던 동안에도
엔딩은 승인된 `fallback_record_text` 로 정상 종료했다 — `DEC-CONTENT-011` 의 "LLM 요청이
실패해도 엔딩 진행과 게임 완료를 막지 않는다" 를 일부러 만들기 어려운 조건에서 확인했다.

**막힌 것**

- 없음. `fear_increments` 승인 3줄과 에셋 ID 명단은 기획 회신 대기이고 진행을 막지 않는다.
