# 작업 로그 — 최수정 (개발)

**Git 커밋에 남지 않는 것만 적는다.** 무엇을 바꿨는지는 `PROGRESS.md`와 diff에 이미 있다.

작성 형식 (해당 없으면 생략):

```
## YYYY-MM-DD 제목

**한 일** — 한두 줄

**왜 이렇게 했나** — 어떤 대안을 검토했고 왜 접었나

**AI가 잘못한 것** — 무엇을 어떻게 잡았나

**막힌 것** — 결정로그에 답이 없는 것. 기획 책임자에게 올릴 목록
```

`AI가 잘못한 것`과 `막힌 것`이 제일 중요하다. 8/8 제출 자료의
「AI 활용 기술 문서」와 「팀원 롤 기술서」를 쓸 때 이 기록이 그대로 재료가 된다.
일주일 뒤에 기억으로 복원하려 하면 대부분 잃어버린다.

이 파일은 개인 전용이라 다른 사람과 충돌하지 않는다.

## 2026-07-31 저장소·개발 환경 구축

**한 일**
기획 문서 3종(결정로그 2,706줄 포함)을 전부 읽고 저장소 구조를 설계했다.
콘텐츠 CSV 31종 스키마, CSV 파싱·검수 모듈, 작업 기록 자동화를 만들었다.

**왜 이렇게 했나**

- **저장소를 새로 팠다.** 민주님 개인 계정 저장소에서는 collaborator가 Settings에
  접근할 수 없어 Pages·Vercel 연결, 시크릿 등록, public 전환이 전부 막힌다.
  배포 담당이 owner여야 했다.
- **`api/` 폴더를 뒀다.** 엔딩 LLM API 키를 브라우저에 둘 수 없다. GitHub Pages는
  서버 코드가 안 돌아서 Vercel 쪽을 보고 있다. 다만 `DEC-CONTENT-011`에
  "사용할 수 없는 LLM 환경"까지 처리 규칙이 있어서, 폴백만 쓰는 것도 정상 경로다.
  배포 방식은 아직 미정.
- **`src/render/viewport.js`와 `asset-resolver.js`를 따로 뒀다.** `DEC-ART-001`이
  보류라 논리 월드 단위 대 픽셀 배율과 에셋 파일 경로가 아직 없다. 이 둘을 두 파일에
  가둬두면 아트 규격이 확정돼도 그 파일만 고치면 된다.
- **`src/core/clock.js`를 뒀다.** 재배 타이머·작물 성장·투척 쿨다운·상태 효과·지원
  공격·회복 게이지가 각각 다른 조건에서 멈춘다. `DEC-INPUT-008`에는 회복 퀵메뉴를
  열면 게임 전체 속도를 낮추는 규칙도 있다. 각 시스템이 시간을 직접 읽으면 이 표를
  지킬 수 없다.
- **`PROGRESS.md`를 자동 생성으로 만들었다.** 시나브로 팀 보고서의 방식(한 파일에
  모두가 append)은 세 명이 쓰면 매번 충돌한다. 그 팀도 문서에 충돌 경고를 달아뒀다.
  git 이력이 이미 정확한 원본이라 재생성 방식으로 바꿨다.

**AI가 잘못한 것**

스키마 31종을 만들면서 **DEC에 없는 문장 734개를 내가 지어냈다.** 필드마다 "기획자가
적을 내용"을 쓴 `guide` 154개, DEC 문장을 내 표현으로 요약한 `description` 295개,
결정로그가 "쓰지 않는다"고만 한 기능을 내가 열 이름으로 바꾼 `excluded_fields` 168개다.

문제는 이게 스키마 파일 안에 있으면 **기획 책임자가 정한 것처럼 읽힌다**는 점이다.
`farming_duration_seconds`에 "해커톤 심사용이면 짧은 편이 안전하다"고 적었는데,
이건 결정로그 어디에도 없는 내 판단이었다.

그리고 검증 규칙 2개(`wildlife.used_by_spawn_profile`,
`personality_profile.referenced_by_resident`)는 해당 DEC의 검증 목록에 아예 없는데
내가 추가했다.

전부 걷어냈다. 스키마에는 구조(필드명·자료형·범위·참조)와 근거 DEC ID만 남겼고,
설명이 필요하면 결정로그를 보게 했다. 같은 내용이 두 곳에 있으면 성민님이 DEC를
고칠 때 어긋나기 시작한다.

같은 이유로 `CLAUDE.md`도 원복했다. 성민님 원본 11줄을 45줄로 늘리면서 `AGENTS.md`
규칙을 재진술한 절을 넣었는데, 그 파일 자체에 "이 파일에 같은 규칙을 복제하거나 다시
정의하지 않는다"고 쓰여 있었다. `README.md`와 `01-게임소개.md`의 요약문도 원문 인용과
출처로 교체했다. 게임소개의 조작표는 "선택한 투척 무기 사용"을 "투척 무기 사용"으로
줄이는 식으로 내가 표현을 다듬어 놓은 상태였다.

**세운 기준**: 파일이 무엇이냐가 아니라 **내용이 누구 것이냐**로 판단한다.
게임 규칙·필드 정의·판정 방식은 기획 문서 소유라 인용만 하고, 저장소 구조·npm 명령·
커밋 규칙은 구현 담당이 쓴다. 결정로그에 답이 없으면 지어내지 않고 `open_questions`에
사실만 남긴다.
