## 1. P0 (경위) — 이게 남아 있으면 튜토리얼이 막힌다

### 1-1. 튜토리얼 `use_throwable` 을 완료할 창이 없다

**전성민 결정 → 김민주 구현**

투척은 퀵슬롯 편성이 전제인데(`combat.throwWeapon()` 이 슬롯이 비면
`no_slot_selected` 로 거절) 편성은 `DEC-RESOURCE-015` 상 **정비에서만** 된다.
승인 CSV 는 정비 블록이 `craft_item`(5번)에서 끝나고 전투가 6·7 이라,
**제작을 누르는 순간 5번이 완료돼 정비가 닫힌다.** 제작 전에는 편성할 무기가
없으므로 앞당길 수도 없다.

선택 넷과 추천은 로드맵 11-2 에 있다. **추천은 ① `assign_quickslot` 을 여덟 번째
`completion_key` 로 신설**이다 — 편성은 실제로 플레이어가 배워야 하는 조작인데
지금 튜토리얼에 빠져 있다.

확정이 나면 할 일 (약 30분, 파일별로는 로드맵 4-2 참조)

```
schema/enums.json                   completion_key 에 값 추가
schema/tables/tutorial_steps.json   같은 값 · schema_version 올림
src/data/types.ts                   TutorialCompletionKey 에 한 줄
src/core/events.ts                  quickslot.assigned 이벤트 신설
src/main.ts                         assignQuickslot() 에서 발행 + 구독 한 줄
data/approved/tutorial_steps.csv    편성 안내 한 행 (stage maintenance)
```

`DEC-CONTENT-025` 3번(같은 `stage` 연속)을 지키려면 편성 안내가 정비 블록 **안**,
`craft_item` 바로 뒤여야 한다. `tutorial_step.stages_contiguous` 규칙이 자동으로 막는다.

### 1-2. 고추·찹쌀을 수확하면 `craft_item` 을 완료할 수 없다 — 45%

**전성민 결정 → 김민주 구현·데이터**

### 2-A. LLM 을 어떻게 할 것인가 — 팀 결정

**지금 상태부터.** `api/ending.ts`·`api/journal.ts` 가 edge 함수로 올라가 있고
배포도 확인됐다. 다만 **실제 키로는 한 번도 안 불렸다** — 프리뷰에 키가 없어
지금까지 본 것은 전부 승인된 폴백 문장이다.

**폴백만으로도 제출은 성립한다.** `DEC-CONTENT-011`·`DEC-JOURNAL-003` 이
*"LLM 을 쓸 수 없는 환경에서도 폴백으로 진행한다"* 를 **정상 경로**로 확정했고,
`DEC-UI-024` 는 *"폴백 텍스트를 정상 생성분과 시각적으로 구분하지 않는다"* 로
정했다. 즉 지금 상태로 촬영해도 규칙 위반이 아니고 화면도 자연스럽다.

**그럼 무엇을 정하는가.** 8/8 촬영에서 **기록문이 실제로 생성되는 것을 보여줄
것인가**다. 보여준다면 Vercel Production 환경변수에 실제 키가 있어야 한다.

| 선택 | 무엇을 하나 | 비용·위험 |
|---|---|---|
| **ⓐ 폴백으로 간다** | 아무것도 안 한다 | 0. 다만 "LLM 을 쓴다"는 것이 영상에서 안 보인다 |
| **ⓑ 개인 키를 Production 에 넣는다** | Vercel 환경변수 `ANTHROPIC_API_KEY` 등록 | 한 런에 엔딩 1회 + 일지 최대 4회. **저장소가 public 이라 키는 Vercel 환경변수에만 둔다** — `.env` 는 `.gitignore` 에 있고 커밋되면 즉시 유출이다 |
| **ⓒ 팀 공용 키** | 같은 등록. 비용을 팀이 나눈다 | ⓑ 와 같다 |

**추천은 ⓑ 또는 ⓒ 다.** 이 게임의 기획 의도가 "엔딩 기록문을 LLM 이 쓴다" 인데
영상에서 폴백만 보이면 그 부분이 전달되지 않는다. 호출량도 작다.

**정하면 할 일**

```
Vercel → 프로젝트 → Settings → Environment Variables
  ANTHROPIC_API_KEY   Production (+ 원하면 Preview)
  ANTHROPIC_MODEL     선택. 없으면 api/_llm.ts 의 기본값을 쓴다
재배포 → 5일차 엔딩까지 밟아 기록문이 폴백이 아닌지 확인
```

모델 ID 를 코드에 박지 않은 것은 `DEC-PIPELINE-012` 가 *"생성 모델 변경은 프롬프트
버전 증가 사유가 아니며 런타임 기록의 `generator_model_id` 로 구분한다"* 로
정했기 때문이다. 환경변수로 바꿀 수 있다.

**확인할 때 주의** — LLM 이 살아 있으면 **전날 조우가 일지 문장에 나와야 한다.**
안 나오면 폴백이 그대로 오는 것이고, 그건 화면으로 구분되지 않으므로
(`DEC-UI-024`) 문장 내용을 봐야 안다.

## 7. 작업할 때 지킬 것

8/5~8/6 에 같은 실수가 반복돼서 적어 둔다.

- **만든 것을 그날 배선한다.** 단위 테스트가 통과해도 화면에서는 아무 일이 없을 수
  있다. 8/4 에 네 번, 8/6 에 두 번 더 나왔다 (`raid_notices` · 지원 소비 표시).
- **빌드가 조용히 실패한다.** `vite:html-inline-proxy` 오류로 8/6 에 세 번 깨졌고
  두 번은 낡은 `dist` 로 측정해 **틀린 결과를 맞다고 읽었다.**
  `node_modules/.vite` 와 `dist` 를 지우면 낫는다. **빌드 뒤 `dist` 시각을 본다.**
- **확정문을 한 번 읽고 필요한 줄만 가져오면 나머지는 아무도 다시 안 본다.**
  맵 경계 제한이 `DEC-CONTENT-016` 안에 있었는데 8/1부터 아무도 안 봤다.
- **못 본 것은 못 봤다고 적는다.** 이 문서의 "확인 못 한 것" 이 그것이다.
